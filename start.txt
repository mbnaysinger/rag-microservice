Microsserviço vector-store-gateway

1. Objetivo Principal
Construir um microsserviço de alta performance, focado em observabilidade e abstração, para atuar como um gateway de gerenciamento para múltiplos bancos de dados vetoriais.

O sistema deve ser desacoplado e seguir os princípios do Clean Code e Arquitetura Hexagonal.

2. Escopo de Persistência (On-Premise)
O microsserviço deve ser capaz de se conectar e operar com qualquer um dos seguintes bancos de dados, tratando-os como "plugins" intercambiáveis:

PostgreSQL (com extensão pgvector)

MongoDB (com Vector Search)

MySQL (v9.4+ com suporte a IA)

MariaDB (com suporte vetorial)

3. Arquitetura Central: Hexagonal (Ports & Adapters)
A estrutura do projeto será estritamente dividida para garantir isolamento e testabilidade.

1-api (Camada de Framework):

Responsável pela exposição (ex: REST).

Contém: Controllers, DTOs (Data Transfer Objects) e Converters (para/de modelos de domínio).

2-domain (Camada de Domínio/Aplicação):

Core Lógico: Contém a lógica de negócios pura, sem dependências de frameworks ou infra.

Contém:

models: Entidades de negócio (ex: VectorDocument).

services: Orquestradores de casos de uso (ex: VectorDocumentService).

ports: A chave da abstração. Interfaces (ex: IVectorRepository, IEmbeddingService) que definem os "contratos" que a infraestrutura deve cumprir.

3-infrastructure (Camada de Adapters):

Implementação Concreta: Contém o código que "conecta" o domínio ao mundo real.

Contém:

adapters: As implementações das portas (ex: PostgresVectorRepository, MongoVectorRepository).

repositories: Lógica de acesso direto ao banco.

entities: Modelos de dados específicos do banco (ex: MongoDocumentSchema).

4. Decisão Crítica: A Camada de Persistência Abstraída
A abstração da persistência não será feita por um ORM (como Prisma ou TypeORM), pois eles não abstraem operações vetoriais nativas (<=>, $vectorSearch, etc.).

A abstração será a Porta (IVectorRepository) definida no Domínio.

Os Adapters na camada de infraestrutura implementarão essa porta usando os drivers nativos de cada banco (pg + pgvector, mongodb, mysql2, etc.) para garantir o uso total e otimizado das funções vetoriais específicas de cada um.

5. Logging e Observabilidade
Logging: A biblioteca padrão do projeto será o Pino.

Formato: Todos os logs devem ser estruturados (JSON) para consumo direto por ferramentas como Grafana Loki.

Contexto: Os logs devem ser enriquecidos (ex: traceId, adapter_em_uso) para facilitar o rastreamento em um ambiente distribuído.

6. Requisitos de Negócio (Embeddings & Chunking)
Chunking (Ingestão): Utilizar a biblioteca LangChain para as funcionalidades de DocumentLoaders (ex: PDFLoader) e TextSplitters (RecursiveCharacterTextSplitter), garantindo a melhor extração de chunks semânticos.

Vetorização (Dimensão): O sistema deve ser configurado para o padrão VECTOR(3072), correspondente ao text-embedding-003 da OpenAI.

Integridade: O fluxo de serviço deve garantir atomicamente que o vector salvo no banco de dados corresponde 100% ao chunk.pageContent do qual foi gerado.

7. Entregáveis e Padrões
Padrões: Todo o código-fonte (nomes de variáveis, funções, classes) deve ser escrito em inglês.

README: O projeto deve conter um README.md detalhado, com foco em um onboard amigável para novos desenvolvedores (setup, variáveis de ambiente, como rodar os bancos com Docker, etc.).

Plano de Ação: O desenvolvimento deve seguir um TODO claro (conforme estrutura sugerida anteriormente), validando cada etapa da implementação, desde as fundações até os adapters específicos.

exmeplo de adapter para postgre:

// Exemplo com node-postgres (pg) e pgvector
import { Client } from 'pg';
import { IVectorRepository, SimilaritySearchResult }
  from '../../2-domain/ports/vector-repository.port';
import { VectorDocument } from '../../2-domain/models/vector-document.model';
import { Logger } from 'pino'; // Injete o Pino

// É crucial instalar a extensão 'pgvector' no seu driver
import 'pgvector/pg';

export class PostgresVectorRepository implements IVectorRepository {
  private client: Client;
  private logger: Logger;

  // Injeção de Dependência (Logger e Config)
  constructor(config: any, logger: Logger) {
    this.client = new Client(config.database.postgres);
    this.logger = logger.child({ adapter: 'PostgresVectorRepository' });
  }

  async setupInfrastructure(): Promise<void> {
    this.logger.info('Setting up Postgres infrastructure...');
    await this.client.connect();
    await this.client.query('CREATE EXTENSION IF NOT EXISTS vector');
    await this.client.query(`
      CREATE TABLE IF NOT EXISTS documents (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        content TEXT,
        metadata JSONB,
        embedding VECTOR(3072) -- O seu requisito
      )
    `);
    // Exemplo de índice (HNSW é geralmente melhor para performance)
    await this.client.query(`
      CREATE INDEX IF NOT EXISTS ON documents
      USING ivfflat (embedding vector_l2_ops) WITH (lists = 100)
    `);
    this.logger.info('Postgres infrastructure ready.');
  }

  async save(document: VectorDocument): Promise<void> {
    this.logger.debug({ docId: document.id }, 'Saving document to Postgres');
    const query = `
      INSERT INTO documents (id, content, metadata, embedding)
      VALUES ($1, $2, $3, $4)
      ON CONFLICT (id) DO UPDATE
      SET content = $2, metadata = $3, embedding = $4
    `;
    // O driver 'pgvector/pg' converte o array JS para o formato do PG
    await this.client.query(query, [
      document.id,
      document.content,
      document.metadata,
      document.embedding, // Passa o array [0.1, 0.2, ...]
    ]);
  }

  async similaritySearch(embedding: number[], topK: number): Promise<SimilaritySearchResult[]> {
    this.logger.debug({ topK }, 'Performing similarity search in Postgres');
    const query = `
      SELECT
        id,
        content,
        metadata,
        1 - (embedding <=> $1) AS similarity_score -- Ex: Cosseno
      FROM documents
      ORDER BY embedding <=> $1
      LIMIT $2
    `;
    // O driver 'pgvector/pg' converte o array de busca
    const result = await this.client.query(query, [embedding, topK]);

    return result.rows.map(row => ({
      document: {
        id: row.id,
        content: row.content,
        metadata: row.metadata,
        embedding: [], // Não retorne o vetor completo
      },
      score: row.similarity_score,
    }));
  }
}

exemplo de service chunk:

import { PDFLoader } from "@langchain/community/document_loaders/fs/pdf";
import { RecursiveCharacterTextSplitter } from "langchain/text_splitter";
import { Document } from "@langchain/core/documents";

export class DocumentLoaderService {
  // ...
  async loadAndSplit(filePath: string): Promise<Document[]> {
    // 1. Loader (Exemplo com PDF)
    const loader = new PDFLoader(filePath);
    const rawDocs = await loader.load();

    // 2. Splitter
    const splitter = new RecursiveCharacterTextSplitter({
      chunkSize: 1000,
      chunkOverlap: 200,
    });

    const chunks = await splitter.splitDocuments(rawDocs);
    return chunks;
  }
}
